How to read this

The skill asks one question of the codebase: should these pieces change together? Problems fall into three wrong answers plus special cases.

  • Hidden link — pieces that must change together, but the code does not show it.
  • Needless link — pieces tied together that change for different reasons.
  • Surplus — pieces with no reason of their own to change (wrappers, dead, speculative).
  • Special case — code for one situation instead of a design that accounts for it.

Safety is risk of applying the proposed fix (behavior, schema, cancellation, CI/JSONL). Impact is how much the fix would help agents (read less, break less silently, debug faster). Prioritize high-impact / low-or-medium-safety first; schedule high-safety work with a plan and tests.

Proposed fixes

Each fix is written above the problems it solves, as in the skill’s decision log. Rank is a suggested implementation order for agent leverage.

F1 · Make terminal ownership a single typed mode

Rank 1 CLI / Core / Runners Impact high Safety medium

Introduce one RunPresentationMode { Text | Quiet | Tui | Jsonl } applied once when constructing the engine/runner. Non-CLI crates return structured lines/events; CLI alone renders. Delete quiet dual-writes and scattered println! policy.

Why this is the top pick: the repo already documents this rule, but call sites still hand-apply quiet flags. Fixing it removes a whole class of TUI/JSONL silent breaks agents keep reintroducing. Git shows run.rs / workflow/run.rs / jssg/run.rs as high-churn (54 / 34 / 46 commits since Aug 2025).

Safety notes: user-visible output and CI JSONL change shape. Mitigate with golden CLI tests for text/quiet/jsonl and a TUI smoke path. Do not change workflow semantics.

    F2 · One generated capability & language catalog

    Rank 2 Sandbox / Semantic / Types Impact high Safety low

    Own module IDs, LLRT allowlists, publish externals, TS declarations, extension→language maps, and dynamic language inventories in one catalog that generates Rust + TypeScript. Install codemod runtime modules through a single helper used by every engine.

    Safety notes: mostly mechanical consolidation. Risk is missing a publish external or WASM module id; mitigate by generating both sides and adding a CI check that native/WASM/types inventories match.

      F3 · Typed matrix identity, cancel, and execution profile

      Rank 3 Models / Core / Scheduler Impact high Safety medium

      Replace string conventions with types: MatrixMeta / identity fields for hashing, TaskStatus::Canceled, and ExecutionProfile::Normal | Preview instead of four pro-dry-run flags. Share one deterministic hashing implementation across recompile detection and task identity, but keep separate inputs and metadata policies: state-change fingerprints the workflow state that should trigger recompile; task identity fingerprints matrix items and continues to exclude _meta_ fields (see test_meta_key_exclusion) so shard identity does not churn when file metadata changes.

      Safety notes: touches persisted task status and matrix hashing. Needs schema migration awareness and resume/cancel regression tests. Preview profile should preserve today’s dry-run semantics bit-for-bit first. Do not merge the two fingerprint semantics into one key — that can recreate shard tasks or suppress real state-change detection.

        F4 · Pass an EventBus; one task-log writer

        Rank 4 Core runtime Impact high Safety medium

        Delete the process-global workflow event sink map. Inject an EventBus into Engine/services. Make TaskStateService the only path that mutates task logs and publishes log events.

        Safety notes: nested runs and tests that relied on ambient registration can miss events until wired. Mitigate by requiring the bus at construction and failing closed in tests.

          F5 · Shared post-run presenter for run / workflow / jssg

          Rank 5 CLI Impact high Safety low

          Keep package-resolve and raw-jssg as front doors only. Share one post-run presenter for metrics, report decision, ExecutionReport, and report server launch. Rename/replace harness-only commands/output.rs with a real CLI emit module.

          Safety notes: mostly dedup. Watch jssg-specific summary fields and report gating flags; snapshot the three command outputs before and after.

            F6 · Split Engine into typed runtime ports

            Rank 6 Core Impact high Safety high

            Carve engine.rs (~5248 LOC, 92 commits since Aug 2025) into WorkflowSchedulerLoop, StepRuntime, and TaskLifecycle, with one task executor that both the main loop and resume/trigger paths use. Move real step bodies out of Engine pass-throughs.

            Safety notes: highest behavioral risk. Matrix recompilation, resume, cancellation, and nested runs all live here. Do only after F1/F3/F4 reduce cross-cutting conventions, and land behind a large butterflow-core test pass.

              F7 · One registry client and auth DTO

              Rank 7 CLI / Core registry Impact high Safety medium

              Collapse parallel token types and move publish HTTP into the shared RegistryClient. CLI keeps OIDC/storage UX only.

              Safety notes: auth field stripping and publish multipart must stay compatible with the hosted registry. Cover login/whoami/publish/ download with contract tests against recorded responses.

                F8 · Split harness_adapter by concern

                Rank 8 CLI AI / harness Impact medium Safety medium

                Break the ~6852-line harness god module into per-harness adapters plus shared lock/state. Keep CLI output enums out of adapter internals. Treat lock sleep/retry as an explicit lock protocol, not a buried special case.

                Safety notes: install/update paths are user-facing and filesystem-touching. Split mechanically with characterization tests per harness before behavior changes.

                  F9 · Keep models pure; move expression evaluation

                  Rank 9 Models / Core Impact medium Safety low

                  Leave AST/types in butterflow-models. Move evaluation and CODEMOD_TASK_* env binding into a workflow-expr/core module with an explicit context builder.

                  Safety notes: expression behavior must stay identical; migrate with existing variable/engine tests. Low user-facing risk if evaluation is moved without rewriting semantics.

                    F10 · Delete surplus and make generation honest

                    Rank 10 Sandbox / Semantic / Packages Impact medium Safety low

                    Remove dead speculative APIs and unused noop provider; point package exports at real modules; ignore committed generated TS or fix headers to name the real generator; force semantic fixtures through the factory.

                    Safety notes: low if limited to unused symbols and packaging paths. Confirm no external consumers of type_info / NoopSemanticProvider before deletion.
