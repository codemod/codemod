# Parity gaps: what `main`'s YAML engine does that the TS engine does not (yet)

Refs and how to read this list:
- **Repos:** YAML = `codemod` `main` @ `0d66d565` (paths under `crates/`). TS = `prototype/typescript-orchestration` @ `72865ebd` (paths under `packages/orchestration/`). `app:` = the `codemod-app` repo.
- **Severity** means severity *for replacing the engine*:
  - **Blocker:** existing users or the platform break.
  - **Major:** a shipped feature disappears.
  - **Minor:** polish, or a niche feature.
- **Effort** is a rough estimate in engineer-days for someone who knows both codebases. It covers code plus tests, and leaves out docs.

## Where the TS engine is ahead

| Area | TS evidence | YAML today |
|---|---|---|
| Typed data flow between steps; one channel (return values) | `src/authoring/runnable.ts:159` (input/output schemas), `src/authoring/composition.ts:136` | 5 untyped channels; `steps.<id>.outputs` not wired (`core/src/engine.rs:2508`, `:3143`, `:4038`) |
| Compile-time detection of wiring errors | `side-by-side.md` T1–T5 | Y1, Y7 and Y8 pass validation; Y8 silently skips the migration |
| Control flow is plain code (if, loops, map → parallel) | `src/authoring/dynamic.ts:9`, `README.md:157` | `if:` strings (evalexpr), a static DAG, a matrix |
| Speed | Measured on real registry workflows with the worker pool (`../perf-pool/summary.md`): TS beats YAML + signal on every heavy cell (react-19 on excalidraw 7.1–8.4 s vs 12.7 s; debarrel on cal.com 17.0–21.4 s vs 33.5 s; audit pack on cal.com 13.2–17.3 s vs 78.8 s), with 1.3–5.6x less CPU; `ts-quickjs` is fastest in every non-trivial cell | YAML + signal still starts about 50 ms faster on tiny runs; stock YAML waits 1–2 s after every run in its poll loop |
| JSSG commit per command is all or nothing, and cross-file conflicts are detected | `HANDOFF.md:41-45`, `src/execution/jssg.ts` | writes file by file mid-batch (`core/src/jssg_execution_service.rs:899-906`) |
| Deterministic replay with nondeterminism detection | `src/runtime/gate.ts:26`, `src/core/errors.ts:15` | resume re-runs tasks from stored status |
| Inline transforms next to the workflow, bundled with their imports | `src/bundle/build.ts:1-21` | separate `js_file`, which must sit inside the workflow dir |
| Unit-testing workflows with scripted completions | `src/host/harness.ts` | engine tests only |
| Weighted admission across shell/jssg/agent/assessment | `src/execution/scheduler.ts:130`, `:183` | per-step `max_threads` |
| Assessment step (TypeSafe, file-oriented, typed answers) | `src/authoring/runnable.ts:511` | none |
| Run dashboard | `src/host/dashboard/*` | TUI only |
| Smaller orchestration core | 3,843 vs 6,491 lines (`engine-size.md`) | n/a |
