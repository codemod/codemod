---
title: "Returning data"
description: "Hand back what a transform finds in each file, and analyze it in the workflow"
---

A transform can return data along with its edit. The data can be any JSON value, and the workflow gets every file's data back to analyze however it likes. This is useful for:

- **Codebase analysis**: find patterns, prop usages, component instances
- **Migration tracking**: record what your codemod rewrote, grouped by the shape of the change
- **Read-only codemods**: gather insights without modifying code

## When to return data

| Package type | Expectation |
| --- | --- |
| Transform / migration step | Return `{ edit, data }` with an entry for each change you make. Add a field for the variant, such as `shape: "no-options"` or `kind: "call-rewrite"`, so the workflow can group them. |
| Read-only mining / Insights | Return `{ edit: null, data }` so the transform reports matches without changing files. |

For standalone JSSG tests, the data is snapshotted in `data.json` next to the fixtures (see [Testing](#testing)).

## Basic usage

Return `{ edit, data }` instead of a string:

```typescript
import type { Codemod } from "codemod/ast-grep";
import type TSX from "codemod/ast-grep/langs/tsx";

const codemod: Codemod<TSX> = async (root) => {
  const buttons = root.root().findAll({ rule: { pattern: "<Button $$$ />" } });
  return {
    edit: null, // leave the file as it is; a string replaces it
    data: { buttons: buttons.length },
  };
};

export default codemod;
```

- `edit`: the new file content, or `null`/missing to leave the file unchanged. Returning a plain string or `null` still works.
- `data`: any JSON value, including `null`. To skip a file's data, leave `data` out or set it to `undefined`.
- Data that isn't JSON (a function, a `BigInt`) is an error, and so are other keys on the result, so a typo doesn't go unnoticed.

## In a workflow

In `workflow.ts`, per-file logic is a `forEachFile` callback, and what it returns is collected into the step's `outputs`, in path order, leaving out files that returned nothing:

```typescript
import { step, forEachFile } from "codemod/workflow";
import { parse } from "codemod/ast-grep";

export default async function main() {
  const scan = await step("Scan", forEachFile({ language: "tsx" }, (file) => {
    const buttons = parse(file).root().findAll({ rule: { pattern: "<Button $$$ />" } });
    return buttons.length ? { file: file.path, buttons: buttons.length } : undefined;
  }));
  // [{ file: "src/a.tsx", buttons: 2 }, { file: "src/b.tsx", buttons: 1 }]
  const total = scan.outputs.reduce((sum, { buttons }) => sum + buttons, 0);
  return { total };
}
```

A jssg transform's `{ edit, data }` is what `codemod jssg run` and `codemod jssg test` report, and what `workflow.yaml`'s `js-ast-grep` steps collect into their outputs.

## Testing

`codemod jssg test` snapshots the data next to `input` and `expected` as `data.json`, in the same `[{ file, data }]` shape. A missing `data.json` is written on the first run; `--update-snapshots` rewrites a changed one.
