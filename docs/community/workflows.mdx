**Codemod Workflows** run automated code transformations at scale. A workflow is a TypeScript file, `workflow.ts`, that runs **steps**: transforms, scripts, agents and approvals. Every step's result is saved, so a large migration can stop and pick up where it left off.

```ts workflow.ts
import { step, forEachFile, jssg, approval, shell } from "codemod:workflow";

export default async function main() {
  await step("Rename stylesheets", forEachFile("src/**/*.less", (file) => {
    file.rename(file.path.replace(/\.less$/, ".css"));
  }));
  await step("Migrate imports", jssg("./scripts/codemod.ts", { include: "src/**/*.ts" }));
  await step(approval("Run the formatter?"));
  await step("Format", shell("npx prettier --write src"));
}
```

## Core concepts

### Steps

`step(task)` marks durable work. When a step finishes, its result is recorded. If a run fails, fix the step that failed and run `codemod workflow resume`: the steps that already finished are not run again.

Steps start when you call `step()`, so `Promise.all` runs steps in parallel.

### Per-file callbacks

`forEachFile(selector, callback)` runs a callback for every matching file, in parallel. The callback, which may be async, gets a file object it can `write`, `rename` or `delete`, with or without parsing it (`parse(file)` from `codemod:ast-grep`). All changes from a step are applied together after conflict checks.

Code inside steps and callbacks runs in its own isolate, with npm packages, files next to the workflow, and file or network access when the run allows it. The rest of the workflow is kept deterministic, so a resumed run takes the same path. See [The workflow body](/community/workflows/reference#the-workflow-body).

### Tasks

| Task | Purpose |
|---|---|
| `forEachFile` | Edit, rename or delete files with a per-file callback |
| `jssg` | Run a [JSSG](/community/jssg) transform file |
| `astGrep` | Apply ast-grep YAML rules |
| `shell` | Run shell commands for setup, cleanup or external tools |
| `agent` | Hand a prompt to a coding agent |
| `codemod` | Run a package from the [Codemod Registry](https://go.codemod.com/registry) |
| `installSkill` | Install a package's skill into a coding-agent harness |
| `shard` | [Split a migration into groups](/community/workflows/sharding) by directory, codeowner or custom logic |
| `approval` | Wait for a person before continuing |
| `branch`, `commit`, `pullRequest` | Git automation for managed runs |

### State and parameters

Steps can share named values through workflow state (`getState`, `setState`), which is saved with each step. Parameters passed with `--param key=value` reach the workflow as `params`.

### workflow.yaml

Packages written as `workflow.yaml` still run: the CLI translates them into the equivalent TypeScript. Convert a package for good with `npx codemod workflow upgrade`. See the [workflow.yaml reference](/community/workflows/yaml).
