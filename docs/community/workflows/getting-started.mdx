In this tutorial you build one small codemod workflow and grow it a step at a time. It replaces Node.js's deprecated `util.isArray()` and `util.isBuffer()` with `Array.isArray()` and `Buffer.isBuffer()`, removes the `node:util` imports it leaves unused, and formats the files it changed.

Each section adds one idea:

1. [Run a JSSG transform](#1-run-a-jssg-transform)
2. [Return data from the transform](#2-return-data-from-the-transform)
3. [Run a shell command](#3-run-a-shell-command)
4. [Decide what runs next](#4-decide-what-runs-next)
5. [Edit files with a callback](#5-edit-files-with-a-callback)

You need Node.js and git.

## Set up

You work in two directories side by side: the codemod package you are building, and a small project to run it on.

```plaintext
util-is-to-native/   # the codemod package
my-app/              # a project to run it on
```

<Steps>
  <Step title="Create the project to migrate">
    Create `my-app` with two files that use the deprecated checks, and commit them. A run refuses to start on uncommitted changes unless you pass `--allow-dirty`, and a commit lets you see what the codemod changed with `git diff`.

    <CodeGroup>

    ```ts my-app/src/check.ts
    import util from "node:util";

    export function describe(value: unknown) {
      if (util.isArray(value)) return `list of ${value.length}`;
      if (util.isBuffer(value)) return `${value.length} bytes`;
      return typeof value;
    }
    ```

    ```ts my-app/src/format.ts
    import util from "node:util";

    export function join(parts: unknown) {
      return util.isArray(parts) ? parts.join(", ") : String(parts);
    }
    ```

    </CodeGroup>

    ```bash
    cd my-app
    git init && git add . && git commit -m "Before the migration"
    ```
  </Step>
  <Step title="Create the codemod package">
    A package needs a `codemod.yaml` that names its workflow file.

<Tip>
For a real package, start with `npx codemod init`. It also sets up `package.json`, type checking for `workflow.ts`, and a test file.
</Tip>

## 1. Run a JSSG transform

A [JSSG](/community/jssg) transform receives one file's syntax tree and returns the file's new text. This one finds `util.isArray(x)` and `util.isBuffer(x)` calls and rewrites them.

```ts util-is-to-native/scripts/util-is.ts
import type { Codemod } from "codemod/ast-grep";
import type TS from "codemod/ast-grep/langs/typescript";

// util.isArray(x) -> Array.isArray(x), util.isBuffer(x) -> Buffer.isBuffer(x)
const REPLACEMENTS = { isArray: "Array", isBuffer: "Buffer" };

const codemod: Codemod<TS> = async (root) => {
  const edits = [];
  for (const [api, global] of Object.entries(REPLACEMENTS)) {
    for (const call of root.root().findAll({ rule: { pattern: `util.${api}($ARG)` } })) {
      edits.push(call.replace(`${global}.${api}(${call.getMatch("ARG")!.text()})`));
    }
  }
  if (edits.length === 0) return null;
  return root.root().commitEdits(edits);
};

export default codemod;
```

The workflow runs it as a step. `forEachFile` picks the files, here every TypeScript file, and `jssg` runs the transform on each of them in parallel.

```ts util-is-to-native/workflow.ts
import { forEachFile, jssg, step } from "codemod/workflow";

export default async function main() {
  await step("Replace util.is* calls", forEachFile({ language: "typescript" }, jssg("./scripts/util-is.ts")));
}
```

Run it from inside `my-app`:

```bash
npx codemod workflow run -w ../util-is-to-native
```

```plaintext
Run 22b1519c-c2e6-4c72-b76b-fc8094d5828a
▸ Replace util.is* calls
✓ Replace util.is* calls (0.0s)
Done
```

`git diff` shows the three rewritten calls.

A step is durable: when it finishes, its result is saved. If a later step fails, fix it and run `npx codemod workflow resume --id <run-id>`. The steps that already finished are not run again.

## 2. Return data from the transform

The workflow can't see what the transform did yet. Have the transform return data along with its edit: return `{ edit, data }` instead of a string. Each entry in `data` is a named list of rows, and the CLI adds up the rows from every file.

```ts util-is-to-native/scripts/util-is.ts {9,13,17-20}
import type { Codemod } from "codemod/ast-grep";
import type TS from "codemod/ast-grep/langs/typescript";

// util.isArray(x) -> Array.isArray(x), util.isBuffer(x) -> Buffer.isBuffer(x)
const REPLACEMENTS = { isArray: "Array", isBuffer: "Buffer" };

const codemod: Codemod<TS> = async (root) => {
  const edits = [];
  const replaced = [];
  for (const [api, global] of Object.entries(REPLACEMENTS)) {
    for (const call of root.root().findAll({ rule: { pattern: `util.${api}($ARG)` } })) {
      edits.push(call.replace(`${global}.${api}(${call.getMatch("ARG")!.text()})`));
      replaced.push({ api });
    }
  }
  if (edits.length === 0) return null;
  return {
    edit: root.root().commitEdits(edits),
    data: { replaced },
  };
};

export default codemod;
```

The step's result carries the totals as `data`: one entry per distinct row, with its count.

```ts util-is-to-native/workflow.ts {4,6-8}
import { forEachFile, jssg, step } from "codemod/workflow";

export default async function main() {
  const migrated = await step("Replace util.is* calls", forEachFile({ language: "typescript" }, jssg("./scripts/util-is.ts")));

  for (const row of migrated.data.replaced ?? []) {
    console.log(`util.${row.cardinality.api}: ${row.count} replaced`);
  }
}
```

Reset `my-app` and run it again:

```bash
git checkout .
npx codemod workflow run -w ../util-is-to-native
```

```plaintext
Run 3d89667c-4daa-4cac-8d54-0a6c9e0d5d0f
▸ Replace util.is* calls
✓ Replace util.is* calls (0.0s)
```

The CLI also prints the run's totals under `Metrics` when it finishes.

Workflows have no shared state. A step returns what it found, and the workflow hands that to the steps that need it, as you do in the next sections. See [Values between steps](/community/workflows/reference#values-between-steps).

## 3. Run a shell command

Use `shell` for anything a command line already does well. Here, git lists the files the migration changed, and Prettier formats them.

A shell command hands values back by writing `key=value` lines to the file in `$CODEMOD_OUTPUT`. `key@=value` adds a value to a list. The values arrive in the step's result as `values`.

```ts util-is-to-native/workflow.ts {1,10-13}
import { forEachFile, jssg, shell, step } from "codemod/workflow";

export default async function main() {
  const migrated = await step("Replace util.is* calls", forEachFile({ language: "typescript" }, jssg("./scripts/util-is.ts")));

  for (const row of migrated.data.replaced ?? []) {
    console.log(`util.${row.cardinality.api}: ${row.count} replaced`);
  }

  const changed = await step("List changed files", shell(`git diff --name-only | sed 's/^/files@=/' >> "$CODEMOD_OUTPUT"`));
  const files = (changed.values?.files ?? []) as string[];

  await step("Format changed files", shell`npx prettier --write ${files}`);
}
```

Values are JSON, so TypeScript can't know their shape: `as string[]` says what you expect. The second command is a tagged template. Each `${}` value is quoted for the shell, and an array becomes one argument per item, so file names with spaces stay whole.

Shell commands run in the directory you start the run from, which is why you run the workflow from inside `my-app`. Give a step `{ cwd }` to run it somewhere else in the project.

```bash
git checkout .
npx codemod workflow run -w ../util-is-to-native
```

## 4. Decide what runs next

A workflow is a TypeScript function, so a decision is an `if` statement. Two decisions make this workflow safer to run on any repository:

- **Stop early** when the transform found nothing to replace, so the run doesn't list or format anything.
- **Ask first** before formatting, since Prettier may also change lines the migration didn't touch. `approval` pauses the run until a person says yes.

```ts util-is-to-native/workflow.ts {1,6-10,16}
import { approval, forEachFile, jssg, shell, step } from "codemod/workflow";

export default async function main() {
  const migrated = await step("Replace util.is* calls", forEachFile({ language: "typescript" }, jssg("./scripts/util-is.ts")));

  const replaced = migrated.data.replaced ?? [];
  if (replaced.length === 0) {
    console.log("No util.isArray or util.isBuffer calls found");
    return;
  }
  for (const row of replaced) {
    console.log(`util.${row.cardinality.api}: ${row.count} replaced`);
  }

  const changed = await step("List changed files", shell(`git diff --name-only | sed 's/^/files@=/' >> "$CODEMOD_OUTPUT"`));
  const files = (changed.values?.files ?? []) as string[];

  await step(approval(`Format ${files.length} changed files with Prettier?`));
  await step("Format changed files", shell`npx prettier --write ${files}`);
}
```

In a terminal, the run asks you directly. With `--no-interactive`, as in CI, it pauses at the approval and exits:

## 5. Edit files with a callback

Not every change needs its own transform file. `forEachFile` also takes an inline callback, which runs once per file, in parallel, and edits the file through the file object.

After the migration, `check.ts` and `format.ts` still import `node:util` but no longer use it. This step removes the import from every file where that's true:

```ts util-is-to-native/workflow.ts {3,6,17-22}
import { approval, forEachFile, jssg, shell, step } from "codemod/workflow";

const SOURCES = { language: "typescript" } as const;

export default async function main() {
  const migrated = await step("Replace util.is* calls", forEachFile(SOURCES, jssg("./scripts/util-is.ts")));

  const replaced = migrated.data.replaced ?? [];
  if (replaced.length === 0) {
    console.log("No util.isArray or util.isBuffer calls found");
    return;
  }
  for (const row of replaced) {
    console.log(`util.${row.cardinality.api}: ${row.count} replaced`);
  }

  const cleaned = await step("Remove unused util imports", forEachFile({ ...SOURCES, containing: "node:util" }, (file) => {
    if (/\butil\./.test(file.text)) return;
    file.write(file.text.replace(/^import util from "node:util";\n\n?/m, ""));
    return file.path;
  }));
  console.log(`Removed the util import from ${cleaned.outputs.length} files`);

  const changed = await step("List changed files", shell(`git diff --name-only | sed 's/^/files@=/' >> "$CODEMOD_OUTPUT"`));
  const files = (changed.values?.files ?? []) as string[];

  await step(approval(`Format ${files.length} changed files with Prettier?`));
  await step("Format changed files", shell`npx prettier --write ${files}`);
}
```

- `containing` skips files whose text doesn't include `node:util`, before the callback runs.
- `file.write` records the new text. When every file is done, the step checks for conflicts and writes all the changes together.
- What the callback returns is collected in `result.outputs`, here the paths it cleaned.
- The callback runs in its own isolate. It can read outside constants such as `SOURCES`, as frozen copies, but it can't assign to outside variables: return a value instead.

## What you built

A workflow that:

- runs a JSSG transform across a project and reads what it found from `result.data`;
- stops when there's nothing to do, and asks before an optional step;
- hands a shell command's output to the next step through `result.values`;
- edits files with an inline `forEachFile` callback and collects its results.

Every step's result is saved, so a run that fails or pauses picks up where it stopped.
